# Ren long-form: current production entry point

Use for new long-form work; explicit owner instructions for the episode take precedence. Read `REN_LONGFORM_BASELINE.md`, `REN_VIDEO_RULES.md`, and `REN_LONGFORM_CHECKLIST.md`. Older white-only and Kokoro instructions in `CLAUDE.md`, `DECISIONS.md` and legacy renderer documentation preserve historic episodes; they are not current long-form defaults. Prototype files may contain placeholder art; do not treat them as approved production assets.

## Production order and approval

1. Research and check claims and illustrative maths; make a reusable script and asset plan. Seek script approval before voice synthesis, unless the owner explicitly supplies a production-approved script.
2. Inventory approved character art, existing Ren MP4s, backgrounds and props; note provenance and source hashes. Read `cliplib/REN_CLIP_INVENTORY.csv`, then visually inspect the actual clip, mouth, direction, bounds and matte. An `ok` manifest entry or a few sampled frames does not approve an entire window. `ren_explain_hands.mp4` manifest window 9–28 seconds exceeds its measured 9.903-second duration: do not use that window. Never mirror automatically.
3. Create a shot plan using `REN_LONGFORM_SHOT_PLAN_TEMPLATE.csv`. Note each beat's story purpose, scene, type, movement source, clip and source window, direction, prop and contact/grounding, framing and transition. Calculate numbers from shared assumptions and ensure every visible equation remains true in every frame. Types distinguish real clip animation from keyframe/prop movement and still/camera movement.
4. Review the whole plan, particularly the middle: identify runs of visually similar graphics, static exposition, repeated gestures and long presenter absences. A return to Ren around 30–45 seconds is a review prompt, not an automatic cut; let meaningful character action play. Preserve reading time and the approved 5.5s Ren, 2.5s story-still and 3.5s graphic shot maxima. Story-character action is not automatically a story still; classify the actual treatment and obey relevant existing rules.
5. Use approved British Qwen/Qwen3-TTS-12Hz-1.7B-Base voice, reference and x-vector settings. Save and hash narration and settings; reuse completed, approved WAVs on visual revisions. Do not stretch, pad, substitute a voice or retry a quota failure blindly.
6. Produce an approximately 60-second pilot with the real workflow; obtain explicit owner approval before full production. For mid-episode planning use the shot plan and existing stills or a preview already needed; no mandatory extra render or new voice request. Pilot approval does not waive final review.
7. Before full output, verify chosen renderer includes the identity-safe `ren_stage._mip` cache fix and run the applicable staging regression test. Keep source-resolution decoding, calibrated scale, grounded feet, contact shadows, sub-pixel movement, half-open cuts, and inspect mouth, edges, continuity and frame boundaries. Two-frame-insert detection in another renderer is not proof this renderer has it; use a compatible validated check or inspect boundaries and disclose the gap.
8. Run applicable technical, financial, visual and audio QA; retain exact source commit, input hashes, master checksum, QA results, and real approval evidence. Inspect every scene and boundary as required. Automated frame/pose checks do not prove good acting. Report tests or listening NOT RUN, and do not call source or approval verified without evidence. Obtain final owner approval; publication requires separate authorization.
